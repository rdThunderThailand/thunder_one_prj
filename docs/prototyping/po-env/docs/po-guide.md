# คู่มือ PO: ทำ prototype ด้วย AI

ที่นี่คือที่ทำ prototype ที่กดได้จริง ใช้หน้าตาและ component ชุดเดียวกับ ThunderOne ข้อมูลทั้งหมดเป็นของปลอม จะกดอะไรก็ไม่กระทบระบบจริง

## ลูปการทำงาน

1. **Brief**: เปิดงานใหม่ใน AI (Grok Bot / Codex / Copilot / Claude Code) แล้วเลือก repo นี้ ใช้ template ด้านล่าง
   - ถ้าใช้ **Grok Bot**: พิมพ์ในแชตว่า "ทำ prototype ใน repo `rdThunderThailand/thunderone-prototypes`" ตามด้วย brief · Grok Bot จะส่งงานให้ coding agent บน cloud แล้วส่งแผน ลิงก์ PR และลิงก์ preview กลับมาในแชต · สั่งแก้ต่อในแชตเดิม จะได้แก้บน PR เดิม
2. **อ่านแผน**: AI จะอ่าน design system ก่อน แล้วตอบเป็นแผน ว่าจะใช้หน้าแบบไหน component อะไร และไฟล์ไหน ถ้าโอเคให้ตอบว่า **"ok"** ถ้าไม่โอเคให้แก้ที่แผนเลย ถูกกว่ามาแก้โค้ดทีหลัง
3. **ดูผล**: AI เปิด Pull Request ให้ แล้ว Vercel จะโพสต์ลิงก์ preview ไว้ในนั้น กดเข้าไปลองได้เลย (ถ้าเจอหน้า login ของ Vercel ให้แจ้ง dev ขอสิทธิ์หรือลิงก์ bypass)
4. **สั่งแก้**: ใช้ template สั่งแก้ด้านล่าง ครั้งละเรื่อง
5. **Check ไม่ผ่าน (กากบาทแดงใน PR)**: พิมพ์บอก AI ว่า **"แก้ตาม check ที่ fail"** ไม่ต้องรู้ว่ามันคืออะไร
6. **ส่ง dev**: ให้ AI กรอก description ของ PR ให้ครบ แล้วส่งลิงก์ PR ให้ dev

## Template: เริ่ม feature ใหม่

```
Feature: <ชื่อ>
ปัญหา: <ผู้ใช้เจอปัญหาอะไร>
ผู้ใช้: <ใคร เช่น Media operator>
Flow: <กดอะไร → เห็นอะไร → จบที่ไหน>
หน้าที่เกี่ยว: <หน้าที่มีอยู่แล้วในระบบจริง ถ้ามี>
ตัวอย่างข้อมูล: <เช่น "playlist 20 อัน บางอันว่าง">
```

## Template: สั่งแก้

```
หน้า: <ชื่อหน้า หรือลิงก์ preview>
ตรงไหน: <เช่น "ปุ่มมุมขวาบน", "การ์ดแถวที่ 2">
อยากให้เป็น: <ผลที่ต้องการ>
ห้ามเปลี่ยน: <ส่วนที่พอใจแล้ว>
```

แนบ screenshot แล้ววงจุดที่อยากแก้ได้ จะช่วยให้ AI แก้ถูกที่

## AI ถูกตั้งให้ทำอะไรเอง

- อ่าน design system และคำศัพท์ของระบบก่อนเริ่มทุก feature
- แก้ของเดิมทีละจุด ไม่สร้างหน้าใหม่ซ้อน
- บอกทุกครั้งว่าแก้ไฟล์ไหน และหน้าจอเปลี่ยนตรงไหน
- ถามกลับเมื่อไม่แน่ใจว่าหมายถึงส่วนไหน

ถ้า AI ไม่ทำตามนี้ ให้พิมพ์ว่า **"ทำตาม AGENTS.md"**

## สิ่งที่ไม่ต้องทำ / ไม่ควรทำ

- ไม่ต้องต่อข้อมูลจริงหรือ login
- อย่าสั่งให้ AI แก้สี ฟอนต์ หรือ component กลาง ถ้าอยากได้แบบใหม่ ให้เขียนไว้ในหัวข้อ "Component ที่ขาด" ใน PR แล้ว dev จะทำให้
- อย่า merge PR เอง dev เป็นคนตัดสินใจ
