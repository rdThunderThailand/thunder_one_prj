# Browser checklist — AC 12 Content Compatibility

**คู่กับ:** `docs/adr/0019-playlist-content-compatibility.md` · `docs/playlists/plan-create-playlist-step1.md` Phase 3
**ครอบคลุม:** AC 12 + การเก็บ `width`/`height` ตอน upload ที่ AC 12 พึ่งพา
**วันที่:** 2026-08-17 · branch `feat/playlist`

## เตรียม

```bash
pnpm dev            # อย่าใช้ npm — pnpm เท่านั้น
```

**ต้องเตรียมไฟล์เทส 3 ไฟล์** — เพราะ asset ทั้ง 17 ตัวใน prod ตอนนี้ไม่มี `width`/`height` เลย
badge จะไม่ขึ้นกับของเก่าแม้โค้ดถูก (ตั้งใจ — ADR 0019 "ไม่รู้ขนาด = เงียบ")

| ไฟล์ | สเปคที่ต้องได้ | จะใช้ทดสอบ |
|---|---|---|
| **F-ok** | รูปหรือคลิป **1920×1080** | ต้องไม่มี badge |
| **F-aspect** | รูป **4:3** เช่น 1600×1200 | ต้องได้ badge "สัดส่วนไม่ตรง Profile" |
| **F-res** | รูปหรือคลิป **1280×720** | ต้องได้ badge "ความละเอียดต่ำกว่า Profile" |

> ทำเร็วๆ ได้จาก macOS Preview → Tools → Adjust Size หรือใช้รูปอะไรก็ได้ที่รู้ขนาดแน่ๆ
> (ดูขนาดจริงได้จาก Finder → Get Info → More Info) ขอแค่ 3 ขนาดนี้ ไม่ต้องสนเนื้อหา

เปิด DevTools ค้างไว้ทั้ง Network และ Console

## A. เก็บขนาดตอน upload (ของใหม่ — ถ้าบล็อกนี้ไม่ผ่าน บล็อก B ไม่ต้องทำ)

| # | ทำ | ผลที่คาดหวัง | ผ่าน? |
|---|---|---|---|
| A1 | ไป `/publications/create` → step เลือก content → upload **F-ok** | upload สำเร็จ asset โผล่ในคลัง | |
| A2 | ใน Network หา request **POST** ที่ลงท้าย `/media/videos` ดู **Payload** | มี `width: 1920` และ `height: 1080` อยู่ใน body (ก่อนแก้ไม่มี 2 field นี้) | |
| A3 | upload **F-aspect** และ **F-res** ต่อ ดู payload ทั้งสอง | ได้ `width`/`height` ตรงกับขนาดจริงของแต่ละไฟล์ | |
| A4 | ลอง upload ไฟล์วิดีโอที่ browser เล่นไม่ได้ (ถ้ามี เช่น `.mov` ProRes) | **upload ยังผ่าน** ไม่มี error ค้าง — payload แค่ไม่มี `width`/`height` (ตั้งใจ) | |

> A4 ข้ามได้ถ้าไม่มีไฟล์ — เขียนว่า "ข้าม" มา

## B. AC 12 — badge เตือนใน Selected for Playlist

ลบคีย์ `thunderone.playlists.create-draft.v2` ใน Local Storage ก่อนเริ่ม

| # | ทำ | ผลที่คาดหวัง | ผ่าน? |
|---|---|---|---|
| B1 | `/playlists/create` → พิมพ์ชื่อ → **Resolution = 1920 × 1080 (16:9)** → Next | เข้า step 2 ได้ | |
| B2 | เลือก **F-ok** เข้า playlist | ในตาราง "Selected for Playlist" แถวนั้น **ไม่มี** badge สีเหลือง | |
| B3 | เลือก **F-aspect** เพิ่ม | แถวนั้นมี pill เหลือง **"สัดส่วนไม่ตรง Profile"** ข้างชื่อไฟล์ | |
| B4 | เลือก **F-res** เพิ่ม | แถวนั้นมี pill เหลือง **"ความละเอียดต่ำกว่า Profile"** | |
| B5 | เอาเมาส์ชี้ค้างบน pill ของ B3 | tooltip โชว์ขนาดจริง เช่น `1600×1200 · Profile 1920x1080` | |
| B6 | เลือก asset เก่าตัวไหนก็ได้ที่มีอยู่ในคลังก่อนวันนี้ | **ไม่มี** badge (ไม่รู้ขนาด = เงียบ ตาม ADR 0019) | |
| B7 | **ยังกดเลือก/ยกเลิกทุกตัวได้ตามปกติ** รวมถึงตัวที่มี badge | ไม่มีอะไรถูกบล็อก ไม่มีปุ่มที่กดไม่ได้ | |
| B8 | ดูที่ Content Library กริดด้านบน | **ไม่มี** badge บนการ์ดในกริด (ตั้งใจ — เตือนเฉพาะที่เลือกแล้ว) | |

## C. คำเตือนเปลี่ยนตาม Profile (ยืนยันว่าคำนวณสด ไม่ได้เก็บค่าไว้)

| # | ทำ | ผลที่คาดหวัง | ผ่าน? |
|---|---|---|---|
| C1 | ถอยกลับไป step 1 เปลี่ยน **Resolution เป็น 1280 × 720 (16:9)** แล้วไป step 2 | **F-res หาย badge** (ตอนนี้มันตรง profile พอดี) · F-aspect ยังเตือนเหมือนเดิม | |
| C2 | เปลี่ยน Resolution เป็น **1080 × 1920 (9:16)** | คราวนี้ **F-ok กับ F-res ติด badge "สัดส่วนไม่ตรง"** ทั้งคู่ (16:9 บนจอตั้ง) | |
| C3 | เปลี่ยนกลับเป็น **1920 × 1080** | กลับไปเหมือน B2–B4 เป๊ะ ไม่มีค่าค้าง | |
| C4 | กด **Save Draft** แล้ว refresh หน้า เข้าใหม่ | badge ยังแสดงถูกต้องเหมือนเดิม (คำนวณใหม่จาก draft ที่ rehydrate) | |

## D. บรรทัดสรุปใน Review

| # | ทำ | ผลที่คาดหวัง | ผ่าน? |
|---|---|---|---|
| D1 | กลับไป Resolution `1920x1080` แล้วเดินไป step 4 (Review) | ในการ์ด **4. Validation Summary** มีบรรทัดที่ 3: สามเหลี่ยมเหลือง + **"media 2 รายการไม่ตรงกับ Output Profile 1920x1080 — ยังสร้างได้ จอจะย่อ/ขยายให้เอง"** | |
| D2 | ถอยไปเอา F-aspect กับ F-res ออก เหลือแต่ F-ok แล้วกลับมา Review | บรรทัดเดียวกันเปลี่ยนเป็นเครื่องหมายถูกเขียว **"media ทั้งหมดเข้ากับ Output Profile 1920x1080"** | |
| D3 | ดูสถานะบนหัวการ์ด Review | ยังเป็น **Ready to create** ตอนที่มี badge เตือนอยู่ — คำเตือนไม่ทำให้ submit ไม่ได้ | |

## รายงานกลับ

ตอบกลับแค่หมายเลขที่ **ไม่ผ่าน** + สิ่งที่เห็นจริงก็พอ ที่เหลือถือว่าผ่าน
ถ้า A2 ไม่ผ่าน (payload ไม่มี `width`) บอกก่อนเลย — ที่เหลือทั้งหมดจะพังตามโดยอัตโนมัติ
