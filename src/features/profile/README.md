# profile

The logged-in user's own profile page (`/profile`) — new 2026-09-16, part of the shell redesign matching the coordinating session's mockup (Topbar/Sidebar restyle, this page, `account-security`, a Change Password flow). Reached only from `UserMenu`'s "โปรไฟล์ของฉัน"/"การตั้งค่าส่วนบุคคล" items — not in the sidebar (the mockup doesn't list it there). Nests under a shell-level route (`(dashboard)/(shell)/profile`), not any App's `(application)` tree, since it's account-level, not workspace-level.

> **Real for reading, narrow for writing.** Core's `GET /api/core/v1/me` (this app's first use of it — not called anywhere else) returns everything this page shows: email, first/last name, display name, avatar URL, preferred language, timezone, role. But `PATCH /api/core/v1/users/{id}` (the only write path) only accepts `first_name`/`last_name`/a handful of other Add-Employee-style personal fields — `display_name`/`avatar_url`/`preferred_language`/`timezone` are real to *read* but have **no write route anywhere in Core**. See `services/profile-api.ts`'s own header comment.

- `services/profile-api.ts` — `getMyProfile(token)` (server-only, `coreGet("/me", token)`, real) and `updateMyProfile(userId, input)` (client-safe via `/api/proxy`, real, but only `first_name`/`last_name`).
- `components/ProfilePage.tsx` — avatar/name/role/org header + 3 tabs (ข้อมูลส่วนตัว/การทำงานในองค์กร/ช่องทางการติดต่อ). "ข้อมูลส่วนตัว" is real and editable (name only, via `EditProfileModal`); "การทำงานในองค์กร" shows real role/org (from the session, not `/me`); "ช่องทางการติดต่อ" has nothing real to show — `/me` doesn't return a phone number at all, so that row is an honest "-" with an explanatory note rather than a fabricated value. "รูปแบบการแสดงผล" (ภาษา/timezone) reads real values but its "แก้ไข" button is disabled with a tooltip — Core has no write path for either field.
- `components/EditProfileModal.tsx` — the `Modal.tsx`-based edit form (same shape as `people/personnel`'s `EditPersonnelModal`), scoped to exactly the two writable fields.
- Not built: avatar upload (no Core endpoint exists at all — `avatar_url` is read-only everywhere), bio/"เกี่ยวกับฉัน" (no such column exposed by `/me`).
