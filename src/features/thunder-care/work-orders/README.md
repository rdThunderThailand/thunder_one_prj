# thunder-care/work-orders

Thunder Care Provider Side's Technician persona — redesigned 2026-09-08 against the "Technician Workflow: Web ↔ Mobile" diagram + 5 Web screen mockups the user provided (following the same request/build pattern as `service-ops`'s Service Operator and `dispatch`'s Dispatcher persona). Requirement doc §4.4 (Asset Intelligence) — this persona has always straddled Asset Intelligence and Thunder Care; the mockups' own "ASSET WORKSPACE" breadcrumb confirms that, it's not a sign these pages belong elsewhere (contrast with Dispatcher's "Asset" nav item, which really does link out to an existing `asset-intelligence/assets` page instead of building a new one).

> R&D — mock data only, no backend yet.

- `components/TechnicianHomePage.tsx` — "หน้าหลัก": next-job card (with a "นำทาง"/navigate CTA), 4 quick-action cards (ขอสิ่งที่ต้องใช้/แจ้งปัญหา/ขอความช่วยเหลือ/คืนและส่งมอบ — all inert, no mockup detail for what happens after), today's 5-job list, mini map preview. **Replaces** the old English `MyWorkPage.tsx` placeholder outright, at the same base route (`/thunder-care/work-orders`).
- `components/MyWorkListPage.tsx` — "งานของฉัน": the full job list with tabs (วันนี้/กำลังดำเนินการ/เสร็จสิ้นวันนี้/ทั้งหมด), distance/ETA columns, priority dots. New route (`/my-work`) — doesn't reuse the old `/assigned` path since the new page is a different shape (job-centric with distance/priority, not the old severity/issueId-linked `WorkOrder` shape).
- `components/MyAssetsPage.tsx` — "ทรัพย์สินของฉัน": every Asset the technician has installed/serviced, with status (ใช้งานอยู่/บำรุงรักษา/หยุดใช้งาน/ยกเลิก).
- `components/MyRequestsPage.tsx` — "คำขอของฉัน": supply/loan/tech-support/document/return requests, each with its own multi-step progress trail (`MyRequestRow.steps`/`currentStepIndex`) since different request types have different step sequences in the mockup (compare REQ-2025-0056's ส่งคำขอ→รออนุมัติ→จัดเตรียม→ส่งมอบ→เสร็จสิ้น against REQ-2025-0048's shorter ส่งคำขอ→อนุมัติ→ดำเนินการ→เสร็จสิ้น).
- `components/ReturnsHandoverPage.tsx` — "การคืนและการส่งมอบ": การคืนอุปกรณ์/การส่งมอบอุปกรณ์ tabs over one `returnHandoverRows` list (filtered by `kind`), each linked back to the Work Order that triggered it.

**Untouched — real cross-feature dependencies, do not change their shape:**
`mockWorkOrders`/`WorkOrder`/`WorkOrderStatus`/`getMockWorkOrders()`/`todaySummary` and `mockTechnicians`/`TechnicianOption` in `mock-data.ts`, plus `WorkOrderCard.tsx`, `AssignedPage.tsx`, `CalendarPage.tsx`, `MiniCalendar.tsx`, `calendar-grid.ts` — `getMockWorkOrders`/`WorkOrderCard` are read directly by `asset-intelligence/assets`'s org-wide Work Orders page (AM-06), `mission-control`, and `intelligence`'s mock data; `mockTechnicians` is read by `thunder-care/service-ops`'s (untouched) `WorkQueuePage`. The new pages above use an entirely separate mock-data section (`todayJobs`/`TechJob` and friends) rather than extending the shared shape, specifically so this round's changes can't accidentally break those other three features. `Assigned`/`Calendar` stay reachable via the sidebar's `standaloneLinks` even though the new mockups' own sidebar doesn't show them.

**Reused, not rebuilt:** "คลังอะไหล่ / อุปกรณ์" links to `thunder-care/dispatch`'s `InventoryPage`; "คลังความรู้" links to `thunder-care/service-ops`'s `KnowledgeBasePage`. **Not built:** "พื้นที่ทำงานของฉัน" and "แจ้งปัญหา" (both named in the mockups' sidebar, no screen mockup provided yet) — both nav items render inert.
