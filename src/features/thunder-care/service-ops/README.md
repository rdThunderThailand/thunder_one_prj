# thunder-care/service-ops

Thunder Care Provider Side's Service Operator persona — full redesign 2026-09-08 against the Service Operator screen mockups + usage-flow diagram the user provided (5 screens: หน้าหลัก, เคสจากลูกค้า, Triage, ติดตามเคส, คลังความรู้). Replaces the earlier English "Customer Health" R&D placeholder (requirement doc §4.6) outright.

> R&D — mock data only, no backend yet. A real version would read case/ticket data from whatever service Thunder Care's real API turns out to be (not scoped yet); see `mock-data.ts` for the exact shape each mock list/panel is standing in for.

- `components/ServiceOpsPage.tsx` — "หน้าหลัก": today's 5 dashboard stats, the "เคสเข้าใหม่ (รอ Triage)" table, SLA Risk / "รอข้อมูลลูกค้า" sidebars, issue-category donut / channel-breakdown / announcements row.
- `components/CasesInboxPage.tsx` — "เคสจากลูกค้า": full inbox across every channel, tab-filterable by status (ทั้งหมด/ยังไม่ได้จัดการ/รอข้อมูลลูกค้า/รอ Triage), row click opens a detail panel (description, attachments, activity log) with a "เริ่ม Triage" link into `TriagePage`.
- `components/TriagePage.tsx` — "Triage", two modes in one component: the **queue** (default — stats, tabs, filterable table, SLA Risk/waiting-for-customer/announcement sidebars) and the **detail+form** view (pick a case → completeness checklist → Service Category/Type, Issue Category, Priority, Complexity, Recommended Action → "บันทึกและส่ง" → "ส่งสำเร็จ, Ready to Dispatch"). Reachable pre-selected via `?case=<id>` (from `ServiceOpsPage`'s and `CasesInboxPage`'s row actions) or by clicking a queue row's own "Triage" button.
- `components/CaseTrackingPage.tsx` — "ติดตามเคส": tracking table (สถานะ/ความเร่งด่วน/SLA/ผู้รับผิดชอบ), row click opens a detail panel with the case's progress timeline (checkmarks for done steps, open circles for pending).
- `components/KnowledgeBasePage.tsx` — "คลังความรู้": category grid, featured/popular articles, how-to guides, quick links, latest updates. ภาพรวม/หมวดหมู่ tabs; every article/link is a disabled "ยังไม่เปิดใช้งาน" placeholder (no article-reading page built).
- `components/CustomersPage.tsx`/`WorkQueuePage.tsx`/`ReportsPage.tsx` — untouched, still the original English placeholders. Not part of the new mockups' sidebar but kept reachable via `standaloneLinks` rather than deleted, since they're real built pages with no replacement designed yet.
- `status-colors.ts` — `issueStatusBadge` (still used by the three untouched pages above) plus `priorityBadge`/`slaRiskTextColor`/`channelIcon`/`inboxStatusColor` for the redesigned pages.
- `mock-data.ts` — `CustomerRow`/`mockCustomers` kept for `CustomersPage`; everything else is new. **Each page has its own mock array**, not one shared source of truth — the four screen mockups aren't fully consistent with each other (e.g. TC-20518 is "ยังไม่ได้จัดการ" on the เคสจากลูกค้า mockup but "กำลังเดินทาง" on the ติดตามเคส one — different illustrative moments, not one snapshot), so forcing a single unified case list would misrepresent the source material rather than faithfully reproduce it. Per-case extra detail (description/attachments/activity, tracking timeline) is only mocked for the specific case each mockup actually shows selected (`getCaseDetail`/`getCaseTimeline` fall back to a generic placeholder for every other id).

**Not built this pass**: Dispatcher's and Service Manager's own workspaces (no mockup yet — only small summary cards in the provider-side overview diagram); actually reading a knowledge-base article (every card/link there is inert); the compact filter dropdowns and per-row checkboxes across all four new list pages (decorative, same "not built yet" convention `people/personnel`'s `PersonnelFilterBar` already established — real filtering needs a backend).
